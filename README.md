# 터틀 트레이딩 스크리너 (리처드 데니스/윌리엄 에크하르트)

돌파매매 스크리너([breakout-screener](https://github.com/changho105-dotcom/breakout-screener))와 **완전히 별개의 신규 프로젝트**입니다.
데이터 수집·배치처리(`lib/krSource.js`, `lib/usSource.js`, `lib/batch.js`)와 서버/화면 구조는 그 앱의 "루틴"을 그대로 가져왔고,
매매 로직(지표·백테스트 엔진)은 미너비니 트렌드템플릿이 아니라 **터틀 트레이딩 룰**로 완전히 새로 짰습니다.

## 터틀 규칙 → 코드 매핑

| 원조 터틀 규칙 | 이 앱에서의 구현 | 위치 |
|---|---|---|
| N (변동성, ATR 유사) | 20일 True Range를 Wilder 방식으로 평활, **2010년부터의 전체 이력** 기준 | `lib/turtleIndicators.js` `computeNSeries` |
| System 1: 20일 채널 돌파 진입 / 10일 채널 이탈 청산 | 동일 | `lib/turtleIndicators.js` `CONFIG.systems.S1` |
| System 2: 55일 채널 돌파 진입 / 20일 채널 이탈 청산 | 동일 | `CONFIG.systems.S2` |
| System1/System2 **동시 운용** | 종목마다 두 시스템을 항상 같이 시뮬레이션 (스크리너·백테스트 공통) | `lib/turtleEngine.js` `runTurtleSystems` |
| System 1 휩쏘 필터(직전 트레이드가 승리면 다음 신호 스킵) | System1에만 적용, System2는 미적용(원문 그대로) | `lib/turtleEngine.js` |
| 손절 = 진입가 - 2N | 유닛별이 아니라 **전체 포지션 기준**, 유닛 추가 시 최신 유닛 기준으로 상향 조정 | `lib/turtleEngine.js` |
| 포지션 사이징 = (자본×1%) / N | 가상자본(1억, 결과는 스케일 불변) 기준으로 유닛당 수량 산정 | `lib/turtleIndicators.js` `CONFIG.unitRiskPct` |
| 피라미딩: 0.5N마다 유닛 추가, 최대 4유닛, **하루에 여러 유닛도 가능** | 갭 상승으로 트리거 여러 개를 하루에 넘으면 그만큼 한 번에 추가 | `lib/turtleEngine.js` (while 루프) |

## ⚠️ 원조 터틀 시스템과 다른 점 (의도적 단순화)

- **Long-only**입니다. 원조 터틀은 채널 하단 이탈 시 숏도 매매하지만, 이 앱은 국내/미국 현물 매수만 다룹니다.
- **System1/System2가 완전히 독립적으로 각자 최대 4유닛을 운용**합니다. 원조 터틀 룰 문서에는 한 시장의 전체 유닛 상한(보통 4개)을 두 시스템이 공유하는 해석도 있지만, 서로 다른 시점에 진입한 유닛들을 하나의 손절 규칙으로 합치는 방식이 여러 갈래로 해석될 수 있어 이 앱은 "시스템별 독립 4유닛"으로 단순화했습니다 — 같은 종목에 두 시스템이 동시에 신호를 내면 최대 8유닛까지 노출될 수 있습니다.
- **원자재 선물이 아니라 주식**이라 N을 계약단위가 아닌 "주당 가격 변동폭"으로 그대로 사용합니다.
- 진입/청산 신호는 종가 기준으로 확정하고 **익일 시가에 체결**된다고 가정합니다(스크리너/백테스트 기준. 페이퍼 트레이더는 배치 스크립트 특성상 트리거가 자체 체결로 근사). 원조 터틀은 장중 스탑주문 체결이 원칙이라 일봉만 쓰는 이 앱은 근사치입니다.
- `maxHoldDays`(300거래일) 강제청산은 원조 터틀에는 없는 안전장치입니다.

## ⚠️ 2010년~현재 전체 이력 사용 관련 주의사항

스크리너·백테스트는 종목별로 **2010-01-01부터 전체 일봉**을 조회해서 N/채널을 계산합니다(예전엔 최근 300일만 써서 System2의 55일 채널이 부정확해지는 문제가 있었음 → 이번에 해결).

- 전체 이력 조회라 스크리너 첫 로딩(캐시 만료 후)이 국내 약 6초, 미국 약 9초 정도 걸립니다(로컬 테스트 기준. Railway 배포 후에는 네트워크 상황에 따라 달라질 수 있음). 30분간 캐시됩니다.
- 차트 모달은 응답 용량을 위해 최근 320봉만 그립니다(신호/손절선 계산 자체는 항상 전체 이력 기준으로 정확함).

### ⚙️ 국내(KR) 데이터 컷오프 스위치 (`lib/krSource.js`의 `HISTORY_END_KR`)

2025년 11월~2026년 상반기 코스피가 2600→9114(2026-06-22 정점)→6300대로 급등락한 버블+폭락 구간이 있어([[project_breakout_trading]] 메모리에 기록된 것과 동일 현상), 이 시기를 겪은 종목들은 N(변동성)이 비정상적으로 커지는 문제가 있었습니다(예: 전체이력 그대로 쓰면 삼성전자 N이 현재가의 약 10%까지 커짐 — 2026-08-07 실측). 한동안 국내만 조회 종료일을 2025-10-31로 고정해서 이 구간을 잘라냈었는데, 2026-08-07에 사용자 지시로 다시 해제했습니다.

`HISTORY_END_KR`은 국내 전체(스크리너·백테스트·페이퍼트레이더)를 동시에 얼리고 녹이는 단일 스위치입니다:
- **`null` (현재 상태)**: 컷오프 없음. 국내도 미국처럼 오늘까지의 실시간 데이터로 정상 동작합니다.
- **`'YYYY-MM-DD'`로 설정**: 그 날짜까지로 조회가 고정됩니다. 화면 상단 배너(`/api/screen/kr` 응답의 `krCutoff` 값 기준)와 페이퍼 트레이더 카드(`state.kr.cutoffActive`/`cutoffDate` 기준)에 자동으로 경고가 뜨고, 날짜가 고정돼있으니 페이퍼 트레이더도 매일 같은 데이터를 다시 보게 되어 사실상 그 시점에 멈춥니다(별도 분기 코드 없이 자연스럽게 그렇게 됨).

버블구간 문제가 다시 걸리적거리면 이 상수만 날짜로 바꾸면 됩니다.

## 화면 구성

- **코스피/코스닥, 미국주식 탭**: 종목마다 S1/S2 상태를 각각 표시
  - `진입신호` 오늘 채널 상단 돌파(휩쏘 필터 통과) → 내일 시가 매수 검토
  - `보유중` 이 시스템대로 매매했다면 현재 보유 중 — 유닛 수, 평단, 손절선, 다음 피라미딩 트리거 표시
  - `필터제외` (S1만) 채널은 돌파했지만 휩쏘 필터로 스킵된 상태
  - `관찰중` 아직 돌파 전 — 채널 상단까지 남은 거리 표시
- **백테스트 탭**: 단일 티커 입력 시 S1/S2 각각의 요약카드 + 합산 타임라인, 복수 티커는 비교표
- 종목 클릭 시 S1/S2 진입·청산 채널과 2N손절선이 함께 표시된 차트 모달
- **실전 가상매매 트래커** (`/paper-trade.html`): `paper_trade/daily_update.js`를 매일 실행하면 한화 5천만원 + 달러 5천만원 상당 포트폴리오(포트폴리오당 최대 10슬롯, 슬롯=종목+시스템 조합)로 실제 신호를 따라간 결과가 누적됩니다. 2026-08-07 Day 1 실행 완료(로컬 테스트 겸 실제 시작).
  - ⚠️ 이 배치 스크립트는 속도를 위해 최근 구간만 조회하고 S1 휩쏘 필터는 적용하지 않습니다(스크리너 화면이 더 정확한 기준). 손절/유닛추가 체결가도 갭을 정밀 반영하지 않고 트리거가로 근사합니다.
  - GitHub 클라우드 자동화는 아직 없음 — 매일 사용자가 로컬에서 `node paper_trade/daily_update.js` 실행 후 `git push`하면 Railway가 재배포하면서 최신 상태가 반영되는 수동 방식입니다 (돌파매매 프로젝트와 동일한 운영 방식).
- **정적 데스크 리포트** (`/portfolio_dashboard.html`): `daily_update.js`가 매일 실행 끝에 `paper_trade/renderDashboard.js`로 이 파일을 새로 구워냅니다(마크 미너비니 앱의 `portfolio_dashboard.html`과 동일한 패턴 — 서버 JS 없이 데이터가 그대로 박혀있는 정적 HTML이라 그냥 파일을 열어봐도 되고, 배포된 앱에서 `/portfolio_dashboard.html`로 봐도 됨). 포트폴리오 현황 + 라이브 앱 API에서 가져온 오늘의 시장 스캔(S1/S2 상태분포) + 오늘/최근 로그를 한 페이지에 담습니다. 시장 스캔 조회가 실패해도(라이브 앱 응답 없음 등) 포지션 관리·state.json 저장에는 영향 없음(별도 try/catch).

## 실행

```bash
npm install
npm start
```

`PORT` 환경변수로 포트 조정 가능 (기본 3000). 국내는 네이버 금융(`api.stock.naver.com`), 미국은 Yahoo Finance Chart API를 씁니다.

## 향후 단계 (아직 미구현)

- 페이퍼 트레이더의 신규 진입 스캔에 S1 휩쏘 필터 정확히 반영 (현재는 스크리너만 정확)
- GitHub 클라우드 스케줄러로 페이퍼 트레이더 완전 자동화
